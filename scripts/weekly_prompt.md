You are running as a fully autonomous, unattended job for this repo (the_ai_game_factory), already checked out at your working directory, on a schedule cron job on a persistent server. The cron fires **daily**, but the pipeline only actually produces a new game roughly every 3 days — most firings will find nothing to do (see step 2) and exit almost immediately. This daily cadence exists so that if a run gets killed partway through (e.g. a usage limit), the very next day's firing picks up where it left off instead of a stalled game sitting broken for days. Nobody will review your output before it goes live — follow every step below carefully and do not skip any.

**Critical: this is a single-shot, non-interactive run (`claude -p`). There is no later turn and no notification will ever reach you once this run ends.** The Agent tool defaults to running in the background, which is only safe in an interactive session where a future turn picks up the completion notification — here, backgrounding any Agent call (at any nesting level, including your own call to `game-producer`) strands it forever and wastes the whole run. Every single Agent tool call you make, and every Agent call any subagent you invoke makes, must explicitly pass `run_in_background: false` and be awaited before moving on. Never wait for a "background task" or "completion notification" — there isn't one.

**Checkpoint your progress as you go.** An environment variable `$PIPELINE_LOG` points to a file outside this repo for exactly this purpose: if this run gets killed partway through (a usage limit, a crash, anything), that file — not this conversation — is what tells whoever's debugging it how far things actually got, and is also what the *next* firing reads to know whether to resume.
